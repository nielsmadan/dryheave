## Cause, correction and offline retest

The launch used a dotted override shaped as
`projects."/absolute/workspace".trust_level="trusted"`. Codex 0.153.4's
[override parser](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/config/src/overrides.rs)
splits keys on every dot and does not interpret quoted key segments. The quoted
workspace and its `.cache` component therefore produced the wrong key structure.
Its [config loader](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/config/src/loader/mod.rs)
merges CLI values before project trust discovery, supporting a literal key inside
the value instead.

Dryheave now emits `projects={"/absolute/workspace"={trust_level="trusted"}}`,
using the selected trusted/untrusted value and only the owned workspace. Captured
configuration bytes remain intact. The existing regression cases now decode the
TOML value and require the exact path as a single key, including dots, quotes and
Unicode. The focused retest passed two cases in 0.09 seconds; lint and formatting
also passed. This is offline source/encoding evidence, not another native launch.

Both allocated native attempts were used. The first failed before Codex started
because of the transport argument boundary; this attempt reached trust onboarding.
No third attempt, automatic approval, global trust change, or permission bypass
was performed. Full live task completion after the correction remains unverified.
No A/B model-performance conclusion can be drawn from these attempts.
