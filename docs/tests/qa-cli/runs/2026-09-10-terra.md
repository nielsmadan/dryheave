## Scanner correction and workflow finding

The runner and recovery passed the entire agent config directory to the log
scanner. Codex populated 206 plugin entries and 87 skill entries, exhausting its
256-entry budget. Both now select the owned `sessions` directory for Codex or
`projects` for Claude. The existing entry/depth/byte limits remain intact. Focused
regressions cover unrelated plugin JSONL, log directories appearing after launch,
both agent layouts and entry-limit enforcement. The focused driver/native/recovery
suite passed 25 tests. Retained low-attempt logs also replayed successfully offline
with the corrected root; the original incomplete capture remains unchanged.

Both retries loaded an automatically supplied Superpowers 6.3.0 plugin from their
fresh Codex config roots. Its brainstorming workflow led to an extra approval
question. The scripted simulator had only the empty-label answer and stopped.
This demonstrates actual ambient workflow influence, not a failure to parse the
question or a model's inability to implement whitespace normalization. A future
experiment should explicitly select that plugin policy and either include ordinary
design approval in the simulated user's policy or test a workflow without that gate.
Changing either input requires a new frozen profile/experiment.
